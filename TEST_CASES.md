# Employee Management API – Test Cases

This document maps directly to the automated `pytest` test suite implemented in `tests/test_auth.py` and `tests/test_employees.py`.

| Test Case ID | Test Case Name | Module | Test Scenario | Preconditions | Test Input / Test Data | Expected Result | Actual Result | Status |
|---|---|---|---|---|---|---|---|---|
| **EMP-TC-001** | Root Health Check & Middleware Header | Core / Middleware | Verify `GET /` returns service running status and `log_requests` middleware attaches `X-Process-Time` header. | FastAPI app initialized with test client. | `GET /` (no headers or body) | HTTP `200`, JSON `{"message": "Employee Management API is Running"}`, numeric `X-Process-Time` header `>= 0`. | Returned HTTP `200` with expected message and valid `X-Process-Time` header. | **PASS** |
| **EMP-TC-002** | User Signup Success | Authentication | Verify `POST /auth/signup` registers a new user, assigns default role `"user"`, sets `is_active=True`, and omits password from response. | Isolated empty SQLite test DB. | `{"email": "newuser@example.com", "password": "StrongPassword123!"}` | HTTP `201`, `UserResponse` with integer `id`, `email`, `role="user"`, `is_active=True`, no password fields. | Returned HTTP `201` with expected `UserResponse` and no password fields exposed. | **PASS** |
| **EMP-TC-003** | User Signup Duplicate Email | Authentication | Verify registering with an email already in the database returns `409 Conflict` formatted by the global exception handler. | User `user@example.com` exists in DB. | `{"email": "user@example.com", "password": "AnotherPassword123!"}` | HTTP `409`, JSON `{"success": false, "message": "Email already registered.", "status_code": 409}`. | Returned HTTP `409` with exact custom error JSON payload. | **PASS** |
| **EMP-TC-004** | User Signup Invalid Email Format | Authentication | Verify Pydantic `EmailStr` rejects malformed email addresses during signup. | Isolated test DB. | `{"email": "not-a-valid-email", "password": "StrongPassword123!"}` | HTTP `422 Unprocessable Entity` with validation error referencing `email`. | Returned HTTP `422` with validation error on `email` field. | **PASS** |
| **EMP-TC-005** | User Login Success | Authentication | Verify `POST /auth/login` authenticates valid OAuth2 form credentials and returns a Bearer JWT. | Active user `user@example.com` exists with password `UserPass123!`. | Form data: `username=user@example.com`, `password=UserPass123!` | HTTP `200`, JSON with `token_type="bearer"` and non-empty `access_token` string. | Returned HTTP `200` with valid Bearer JWT `access_token`. | **PASS** |
| **EMP-TC-006** | User Login Invalid Credentials | Authentication | Verify login fails with `401` for both wrong password and non-existent user email. | User `user@example.com` exists in DB. | (1) `username=user@example.com`, `password=WrongPassword!`; (2) `username=ghost@example.com`, `password=AnyPassword123!` | HTTP `401` with `{"success": false, "message": "Invalid email or password.", "status_code": 401}` for both attempts. | Both attempts returned HTTP `401` with exact error message and custom schema. | **PASS** |
| **EMP-TC-007** | Get Current Authenticated User | Authentication | Verify `GET /auth/me` returns profile with valid JWT and rejects missing or malformed tokens with `401`. | Active user `user@example.com` with valid Bearer token. | (1) Valid `Authorization: Bearer <jwt>`; (2) No header; (3) `Authorization: Bearer invalid.jwt.token` | (1) HTTP `200` with user email and role; (2) HTTP `401`; (3) HTTP `401` with `"Could not validate credentials."`. | Returned `200` for valid token and `401` for missing and invalid tokens. | **PASS** |
| **EMP-TC-008** | Inactive User Access Denied | Authentication / Security | Verify a user with `is_active=False` is blocked from protected routes even with a validly signed JWT. | Inactive user `inactive@example.com` (`is_active=False`) with signed JWT. | `GET /auth/me` with `Authorization: Bearer <inactive_jwt>` | HTTP `403 Forbidden`, JSON `{"success": false, "message": "Inactive user.", "status_code": 403}`. | Returned HTTP `403` with exact custom error payload. | **PASS** |
| **EMP-TC-009** | Create Employee Successfully (Admin) | Employees | Verify an authenticated admin can create a new employee via `POST /employees/`. | Active admin user (`role="admin"`) with valid JWT. | `{"name": "Bob Smith", "email": "bob.smith@company.com", "department": "Finance", "salary": 82500.50}` | HTTP `201 Created`, response includes generated integer `id` and all submitted fields. | Returned HTTP `201` with persisted employee data and generated ID. | **PASS** |
| **EMP-TC-010** | Create Employee Forbidden (Non-Admin) | Employees / RBAC | Verify a standard (`role="user"`) authenticated user cannot create an employee. | Active regular user with valid JWT. | `{"name": "Unauthorized Attempt", "email": "unauth@company.com", "department": "HR", "salary": 60000.0}` | HTTP `403 Forbidden`, JSON `{"success": false, "message": "Only administrators can perform this action.", "status_code": 403}`. | Returned HTTP `403` with exact admin-only error response. | **PASS** |
| **EMP-TC-011** | Create Employee Missing Required Fields & Empty Body | Employees / Validation | Verify `POST /employees/` rejects empty `{}` and partially populated payloads. | Active admin user with valid JWT. | (1) `{}`; (2) `{"name": "Incomplete User", "email": "inc@company.com"}` | HTTP `422 Unprocessable Entity` listing missing required fields (`name`, `email`, `department`, `salary`). | Both payloads returned HTTP `422` with expected missing-field details. | **PASS** |
| **EMP-TC-012** | Create Employee Invalid Data Types | Employees / Validation | Verify `POST /employees/` rejects non-numeric `salary` string. | Active admin user with valid JWT. | `{"name": "Bad Type", "email": "badtype@company.com", "department": "Engineering", "salary": "not-a-number"}` | HTTP `422 Unprocessable Entity` referencing `salary`. | Returned HTTP `422` with float parsing validation error on `salary`. | **PASS** |
| **EMP-TC-013** | Create Employee Boundary Values | Employees / Validation | Verify boundary float salary values (`0.0` and `9999999.99`) are accepted and persisted without precision loss. | Active admin user with valid JWT. | (1) `salary: 0.0`; (2) `salary: 9999999.99` with distinct valid employee records | HTTP `201 Created` for both requests with exact salary values returned. | Both boundary records returned HTTP `201` with exact salary values. | **PASS** |
| **EMP-TC-014** | Create Employee Duplicate Email Conflict | Employees / DB Constraints | Verify behavior when creating an employee with an email that violates the `employees.email` unique constraint. | Employee `alice.johnson@company.com` exists; active admin JWT. | `{"name": "Duplicate Alice", "email": "alice.johnson@company.com", "department": "Engineering", "salary": 90000.0}` | HTTP `500` (application currently does not catch SQLAlchemy `IntegrityError`; documented as a known unhandled DB constraint behavior). | Returned HTTP `500` as expected for current unhandled `IntegrityError` implementation. | **PASS** |
| **EMP-TC-015** | Retrieve All Employees (Pagination, Filter, Search) | Employees | Verify `GET /employees/` default `limit=5`, `skip`/`limit` pagination, exact `department` filter, and case-insensitive `search` by name. | 6 seeded employees across `Engineering` (4), `HR` (1), `Finance` (1); regular user JWT. | (1) `/employees/`; (2) `/employees/?skip=4&limit=5`; (3) `/employees/?department=Engineering&limit=10`; (4) `/employees/?search=finance` | HTTP `200`: (1) 5 items; (2) 2 items; (3) 4 Engineering items; (4) 1 item (`Finance Analyst`). | All four query combinations returned HTTP `200` with exact expected counts and records. | **PASS** |
| **EMP-TC-016** | Retrieve Employee by ID (Valid, Non-Existent, Invalid) | Employees | Verify `GET /employees/{id}` for existing ID, non-existent ID, and non-integer path parameter. | Seeded employee record; regular user JWT. | (1) `/employees/<valid_id>`; (2) `/employees/999999`; (3) `/employees/not-an-id` | (1) HTTP `200` with employee record; (2) HTTP `404` with `"Employee not found"`; (3) HTTP `422`. | Returned `200`, `404` (custom JSON), and `422` respectively. | **PASS** |
| **EMP-TC-017** | Update Employee Information & RBAC | Employees / RBAC | Verify `PUT /employees/{id}` supports partial updates (`exclude_unset=True`), returns `404` for missing ID, and `403` for non-admin. | Seeded employee record; admin and regular user JWTs. | (1) Admin `{"department": "Platform Engineering", "salary": 110000.0}`; (2) Admin on ID `999999`; (3) Regular user on valid ID | (1) HTTP `200` preserving unchanged `name`/`email`; (2) HTTP `404`; (3) HTTP `403`. | Partial update preserved untouched fields (`200`); missing ID returned `404`; regular user returned `403`. | **PASS** |
| **EMP-TC-018** | Delete Employee & RBAC | Employees / RBAC | Verify `DELETE /employees/{id}` enforces admin role, deletes record, confirms subsequent `GET` returns `404`, and returns `404` for missing ID. | Seeded employee record; admin and regular user JWTs. | (1) Regular user `DELETE /employees/<id>`; (2) Admin `DELETE /employees/<id>`; (3) `GET /employees/<id>`; (4) Admin `DELETE /employees/999999` | (1) HTTP `403`; (2) HTTP `200` `{"message": "Employee deleted successfully"}`; (3) HTTP `404`; (4) HTTP `404`. | All four assertions matched expected status codes and payloads. | **PASS** |
| **EMP-TC-019** | Database Operational Error Handling | Employees / Error Handling | Verify API behavior when the database session raises a `SQLAlchemyError`. | `get_db` dependency overridden with a mock session raising `SQLAlchemyError`. | `GET /employees/` with admin JWT | HTTP `500 Internal Server Error` (does not fail silently or return `200`). | Returned HTTP `500` when simulated `SQLAlchemyError` occurred. | **PASS** |
